# BRIEFING_PDS — Power Apps Source Code Compatibility Register

**Status:** Active  
**Screen:** `scr_Briefing_PDS`  
**Capability:** `BRF-C01`

Power Apps Studio + App Checker are the final acceptance authority. This register inherits confirmed PULSE rules and records Briefing-specific decisions.

## 2. Inherited rules

### BRF-COMP-001 — `Classic/Button@2.2.0` AccessibleLabel

Do not introduce unsupported `AccessibleLabel` patterns. BRF-C01 does not require Classic/Button.

### BRF-COMP-002 — Radius is control-specific

Apply `RadiusTopLeft/Right/BottomLeft/BottomRight` only to GroupContainer surfaces with demonstrated repository usage. Never assume Label, ModernText or Icon support radius.

### BRF-COMP-003 — Major geometry uses AutoLayout

Use `GroupContainer@1.5.0` AutoLayout for shell/header/body geometry. ManualLayout is limited to bounded content cards.

### BRF-COMP-004 — Static ModernText defaults to AutoHeight

```text
AutoHeight=true
Wrap=false for one-line content
Wrap=true for narrative content
```

This is required by `POWER_APPS_VISUAL_QA_GUARDRAILS.md`.

### BRF-COMP-005 — Custom component definition acceptance is not host-instance safety

Do not infer that a custom component can be safely source-created on a new screen merely because its definition exists.

### BRF-COMP-006 — `cmp_PageHeaderPro` excluded from BRF-C01

Known Home_PDS evidence:

```text
DEFINITION_ACCEPTED                  PASS
MANUAL_INSTANCE_SAFE                PASS
HOST_SOURCE_CUSTOM_PROPERTY_BINDING FAIL/PA2108 pattern
SOURCE_CREATED_INSTANCE_BODY        may not hydrate as expected
```

BRF-C01 therefore builds the header with native compatible controls.

### BRF-COMP-007 — `cmp_SidebarNav` hydration is a localized Studio gate

Evidence is mixed by context:

```text
scr_PunchReview existing hydrated instance   positive serialization reference
Home_PDS new source-created instance          rendered, host inputs ignored
```

BRF-C01 includes the instance because it is part of the required shell, but does not claim host-input hydration until Studio validates it.

Corrective path if required:

```text
keep full Briefing screen
→ delete only cmpBRF_Sidebar
→ insert existing cmp_SidebarNav manually in Studio
→ move as first child of conBRF_ScreenRoot
→ rename cmpBRF_Sidebar
→ configure public inputs
→ save/reopen
```

### BRF-COMP-008 — No custom components inside galleries

BRF-C01 uses no such pattern.

### BRF-COMP-009 — Synthetic state is not functional evidence

`varBRF_TestState`, tab changes, local evidence drawer actions and local send/approve transitions are visual test scaffolding only.

## 3. New-screen Source Code assumptions pending Studio

The following remain `NOT_RUN` until the cumulative source is pasted into Studio:

```text
- screen root accepted
- all native control properties accepted
- ModernCombobox static Table contract accepted in this screen
- horizontal/vertical LayoutOverflow properties behave as intended
- nested responsive AutoLayout geometry remains stable
- sidebar host input assignments hydrate
```

Any PA1001/PA2108 or control-property error generated by Studio must be added to this register before a dependent capability treats the source as canonical.

## 4. Acceptance chain

```text
STATIC_REPOSITORY_REVIEW
→ SOURCE_ACCEPTED_IN_STUDIO
→ APP_CHECKER_CLEAN_FOR_NEW_SCREEN
→ LOCAL_INTERACTION_VALIDATED
→ VISUAL_QA_VALIDATED
→ BRF-C01_ACCEPTED
```

No later stage may be inferred from an earlier one.
